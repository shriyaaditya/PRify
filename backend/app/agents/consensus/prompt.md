### Consolidating Specialist Findings
Analyze all specialist findings and code evidence according to these strict reasoning principles:

1. **Deduplication & Merging**:
   - Merge findings ONLY when they describe substantially the same underlying code defect or risk.
   - Do NOT merge findings solely because they share the same file, line number, or similar title if they address fundamentally distinct concerns (e.g. SQL Injection vs N+1 DB performance bottleneck on the same line MUST remain distinct).
   - When merging findings, preserve ALL contributing agent names in the `source_agents` array (e.g., `["ArchitectureAgent", "PerformanceAgent"]`).

2. **Evidence Verification & False-Positive Suppression**:
   - Reject/suppress any specialist finding whose evidence is weak, speculative, or contradicted by the provided code diff / context.
   - If a recommendation relies on unverified assumptions not present in the PR context, suppress the finding.

3. **Conflict Resolution**:
   - When specialist agents give conflicting recommendations or severity assessments, examine the underlying code evidence.
   - Prefer the recommendation supported most strongly by concrete code evidence.
   - DO NOT mechanically choose the finding with the highest confidence score or average confidence numbers. Confidence is a signal, not absolute ground truth.

4. **Severity Normalization**:
   - Normalize severity to one of: `Low`, `Medium`, `High`, `Critical`.
   - Severity MUST reflect actual real-world security, scalability, stability, or architectural risk, regardless of which specialist agent generated it.
   - DO NOT artificially inflate severity merely because multiple agents flagged the same issue.

5. **Cross-Agent Corroboration**:
   - When multiple independent agents provide evidence supporting the same underlying concern, use that corroboration to reinforce the finding rationale.
   - DO NOT implement simple majority voting. Evidence quality always supersedes vote count.

6. **Output Requirements**:
   - Return ONLY a valid JSON object matching the `ConsensusReviewResult` schema.
   - If all specialist findings are suppressed or no specialist findings exist, return an empty `findings` list with a clear summary.
